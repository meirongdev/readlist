## 1. 背景与问题陈述

私有 Calibre-Web 书库（`book.meirong.dev`）积累了 **2,054 本**技术书。问题不是书不够，
而是**没有排序能力**：

- calibre-web 只能按标题 / 作者 / 添加时间排，回答不了"哪本值得先读"；
- 库内评分只有 **14 本**有值，等于不存在（[data-baseline §1](data-baseline.md#1-书库-metadatadb)）；
- 网上的技术书榜（Goodreads / Amazon / HN Books）排的是**别人的书**，而且全是 1–2 维、
  权重写死的死榜，没法回答"以我现在的目标，该读哪本"；
- 结果是书库变成"下载即遗忘"的堆积 —— **只有 23 本被标记读过**。

要解决两个具体问题：

| | 问题 | 成功的样子 |
|---|------|-----------|
| **对内** | 2,000 本里下一本该读什么？ | 一个「下一本读什么」列表：高分 ∩ 未读，可按目标切换口径 |
| **对外** | 怎么把这个库变成有观点、可解释的公开书单？ | 一个公开站：多口径榜单 + 每本书的得分拆解 + 我读过哪些 |

## 2. 目标 / 非目标

### 目标

1. 一套**可解释、可复算、版本化**的技术书评分标准（不是一个分数，是一组维度 + 组合规则）。
2. 同一批分数下切换**不同评分口径**看不同榜单，并支持读者自行调整权重。
3. 一个**公开**的书单 Web 应用：无需登录浏览榜单、查看每本书的得分拆解与数据来源。
4. 每本书标出**是否已阅读**，可按阅读状态筛选，并由此派生阅读队列。

### 非目标

| 不做 | 原因 |
|------|------|
| ❌ 公开下载 / 在线阅读 / 正文片段 | 版权红线（NFR-12） |
| ❌ 替代 calibre-web | `book.meirong.dev` 仍是私有书库本体；本站只读它的元数据 |
| ❌ 用户注册 / 投票 / 评论 | 没有流量，Wilson 下界那类排序无数据可排；引入写接口只增攻击面 |
| ❌ 在本站修改阅读状态 | 真相源必须唯一（见 [reading-status.md](reading-status.md)） |
| ❌ 全量书评生成 | LLM 只做**结构化标注**（深度/可操作/主题），不生成面向读者的评价文字 |

## 3. 干系人与使用场景

| 角色 | 关心什么 |
|------|---------|
| **库主人**（唯一写入者） | 下一本读什么；书库哪些书元数据烂；读过的书留下痕迹 |
| **公开访客**（无登录） | 某个方向有哪些书值得读；这个排名凭什么；哪些是作者真读过的 |
| **运维**（同一人） | 采集不炸、配额不爆、公开端点不被爬垮 |

### 用户故事

| ID | 故事 | 对应需求 |
|----|------|---------|
| US-1 | 作为库主人，我想看到「高分但我还没读」的书，好决定下一本读什么 | FR-31, FR-40 |
| US-2 | 作为库主人，我要标记读过/在读/想读/弃读，并让榜单反映出来 | FR-41 ~ FR-44 |
| US-3 | 作为库主人，我想知道哪些书元数据残缺，好去补 | FR-24（L 维度）、FR-33 |
| US-4 | 作为访客，我想按"经典长青 / 最快上手 / 深挖原理"切换榜单 | FR-30, FR-31 |
| US-5 | 作为访客，我想自己拖权重滑块，因为我的偏好和作者不同 | FR-32 |
| US-6 | 作为访客，我点开某本书要能看到**它凭什么排这么高** —— 各维度分 + 数据来源 | FR-34 |
| US-7 | 作为访客，我想知道哪些书**作者真读过** —— 真人读过的推荐比算法分可信 | FR-45 |
| US-8 | 作为访客，我不想看到一堆"数据不足硬凑出来"的书混在榜里 | FR-25（证据分级） |
| US-9 | 作为运维，我要在配额耗尽/采集失败时知道，而不是发现榜单静默过期 | FR-60 ~ FR-62 |

## 4. 数据现实（摘要）

完整实测见 [data-baseline.md](data-baseline.md)。对需求影响最大的六条：

| 事实 | 需求含义 |
|------|---------|
| 2,054 本；`metadata.db` 仅 4.4 MB | 全量重算是秒级 → **不需要增量算分**，简化设计（NFR-1） |
| 库内评分 14 本 | 口碑维度**必须**全靠外部源（FR-10 ~ FR-12） |
| ISBN 715（34.8%）+ `google` id 310 | 外部匹配只覆盖约 1/3 → 必须有"证据不足"的显式处理（FR-25） |
| **`pubdate` 477 本被 mtime 污染** | ⚠️ 时效维度有**硬前置**（FR-13、AC-P1） |
| **阅读状态仅 23 本，在 `app.db`** | ⚠️ 管道小、补录大；且 `app.db` 含凭据 → 最小导出（FR-14、NFR-13） |
| 出版社 66% 有，但 Packt 4 个变体 | 权威维度需要**名称归一化**（FR-15） |

## 5. 功能需求

### 5.1 数据接入（FR-1x）

| ID | 需求 | 优先级 |
|----|------|--------|
| FR-10 | 每夜从 `metadata.db` 取一致性快照（`VACUUM INTO`），派生数据全部基于快照，**绝不直连活库** | P0 |
| FR-11 | 从 Google Books / OpenLibrary 抓外部评分与元数据；响应**原样缓存**（含 TTL），重算不打外部 API | P0 |
| FR-12 | 从 HN Algolia 抓社区提及；保留命中 `objectID` 以便人工验证与否决 | P1 |
| FR-13 | 富集写入出版日期时**必须同时记录 `pubdate_source`**；来源不可信的书时效维度记为"未知" | **P0（阻塞）** |
| FR-14 | 从 `app.db` **最小导出**阅读状态（仅 3 张表），只取库主人账号，join 时丢弃孤儿行 | P0 |
| FR-15 | 出版社名归一化表（`publisher_map`），把同一出版社的多个变体合并后再评级 | P0 |
| FR-16 | 通过内部 LLM 网关对每本书产出结构化标注（主题类别/层级/深度/可操作性/置信度），带输入指纹避免重复调用 | P1 |
| FR-17 | 每次采集/评分写 `runs` 记录（起止、成功数、失败数、孤儿行数、配额消耗），供审计与复算 | P1 |

### 5.2 评分（FR-2x）

| ID | 需求 | 优先级 |
|----|------|--------|
| FR-20 | 按 [TBS v1.0](scoring-standard.md) 计算 7 个维度分（0–100），每维分数与其数据来源一并存储 | P0 |
| FR-21 | 口碑维度用**贝叶斯加权**，多源按评分人数加权合并，不做简单平均 | P0 |
| FR-22 | 归一化用**语料内百分位**，不用 min-max | P0 |
| FR-23 | 时效维度按**主题半衰期**指数衰减，不用绝对年龄 | P0 |
| FR-24 | 馆藏可读性维度（纯本地，100% 可算），并可反向输出"待补元数据"清单 | P1 |
| FR-25 | 给每本书判**证据等级 A/B/C/D**；C 只进目录页并标注"数据不足"，D 不公开 | P0 |
| FR-26 | 每行分数带 `standard_version`；改公式或权重 = 发新版本，**不得原地覆盖历史分** | P0 |
| FR-27 | 缺数据一律走贝叶斯收缩到语料先验，**不得当 0 分处理** | P0 |

### 5.3 榜单（FR-3x）

| ID | 需求 | 优先级 |
|----|------|--------|
| FR-30 | 榜单定义为**外置配置**（权重 + 目标带 + 过滤器 + 豁免维度），加榜不改代码、不重算分数 | P0 |
| FR-31 | 内置预设：`timeless` / `ship-this-week` / `deep-dive` / `new-2026` / `ai-llm` / `to-read-next` / `read-and-loved` / `library-hygiene`(内部) | P0 |
| FR-32 | 前端可调权重滑块，即时重排（纯客户端向量点积） | P1 |
| FR-33 | 支持 `visibility: internal` 的榜单（如书库卫生榜），不出现在公开导航 | P1 |
| FR-34 | 书详情页展示**得分拆解**：各维度分、原始值、数据来源、证据等级、标准版本 | P0 |
| FR-35 | 深度这类 facet 维度用**目标带**打分，允许"太深反而减分" | P0 |

### 5.4 阅读状态（FR-4x）

详见 [reading-status.md](reading-status.md)。

| ID | 需求 | 优先级 |
|----|------|--------|
| FR-40 | 榜单每一项显示阅读状态徽章；**未读不显示徽章**（2,000 个"未读"是噪声） | P0 |
| FR-41 | 支持状态：已读 / 在读 / 想读 / 弃读 / 精读；核心三态取 `book_read_link`，其余用 calibre-web 书架承载 | P0 |
| FR-42 | 按阅读状态筛选（全部 / 已读 / 未读），排序逻辑不受影响 | P0 |
| FR-43 | 阅读状态**只读镜像**，本站永不写回；真相源恒为 calibre-web | P0 |
| FR-44 | 阅读状态是 **facet，不进 TBS 分数**（读过 ≠ 好书） | P0 |
| FR-45 | 已读的书在榜单上标"作者读过"，作为与纯算法榜的差异 | P1 |
| FR-46 | `expose_read_status` 开关；`弃读` 书架默认不公开 | P1 |

### 5.5 Web 界面（FR-5x）

| ID | 需求 | 优先级 |
|----|------|--------|
| FR-50 | 榜单页：预设切换 + 权重滑块 + 阅读状态徽章与筛选 | P0 |
| FR-51 | 书详情页：得分拆解 + 外部链接（出版社 / Google Books）+ 阅读状态 | P0 |
| FR-52 | 全库目录页：含 C 级书，显式标注"数据不足" | P1 |
| FR-53 | 只读 API（榜单 / 书详情 / 预设列表），无任何写接口 | P0 |
| FR-54 | 封面图**外链** OpenLibrary Covers / Google Books，不自托管出版商封面 | P0 |
| FR-55 | 移动端可用（榜单是长列表，手机是主要浏览场景） | P1 |

### 5.6 运维与可观测（FR-6x）

| ID | 需求 | 优先级 |
|----|------|--------|
| FR-60 | 暴露 Prometheus 指标：采集成功/失败数、外部 API 配额消耗、各证据等级书数、最后成功采集时间 | P1 |
| FR-61 | 快照/采集/评分任一步失败要能从指标看出来，而不是榜单静默过期 | P1 |
| FR-62 | `runs` 里的孤儿行数异常上升要可见（= 有人在删书或重导入，说明 book id 漂移） | P2 |
| FR-63 | 榜单可**手动触发重算**（改了标准版本之后不必等到夜里） | P2 |

## 6. 非功能需求

| ID | 类别 | 需求 |
|----|------|------|
| NFR-1 | 性能 | 全量评分重算 ≤ 30s（2,054 本，本地 SQLite）；榜单 API P95 < 200ms |
| NFR-2 | 性能 | 前端权重滑块重排在浏览器内完成，无网络往返 |
| NFR-3 | 可用性 | 与 calibre-web **解耦**：calibre 挂了榜单照常服务（读快照，不读活库） |
| NFR-4 | 可用性 | 外部 API 全挂时降级为"用缓存数据出榜"，不整站不可用 |
| NFR-5 | 平台 | 镜像必须含 `linux/arm64`（oracle-k3s 是 ARM free tier） |
| NFR-6 | 平台 | 单副本 + `Recreate` 策略（SQLite 单写锁，滚动更新会抢锁） |
| NFR-7 | 资源 | 内存与 CPU 按同集群 `trends` 应用的量级；命名空间有 LimitRange，须显式声明 request/limit |
| NFR-8 | 成本 | 外部数据源全部走免费额度；LLM 标注走内部网关跑本地 GPU，**零外部推理成本** |
| NFR-9 | 配额 | Google Books 免费额度约 1,000 次/天 → 首轮采集分 2–3 天；持久化缓存，重启不重抓；配额耗尽即停到次日，不空转打 429 |
| NFR-10 | 可复算 | 同一 `standard_version` + 同一份 evidence 快照 ⇒ 分数**逐位可复现** |
| NFR-11 | 可解释 | 任一分数可追溯到原始值与来源；自建榜单唯一的信任来源就是"能看见怎么算出来的" |
| NFR-12 | 合规 | **只发元数据与评分，不发书**：无下载、无在线阅读、无正文片段；与私有书库无跳转关系 |
| NFR-13 | 安全 | ☠️ **绝不整库快照 `app.db`** —— 它含密码 hash、会话、OIDC 凭据；只导出所需的 3 张表 |
| NFR-14 | 安全 | 公开端点无 SSO → 边缘限流（页面与 `/api/` 分别限流）；应用侧只读、无用户输入落库 |
| NFR-15 | 隐私 | 阅读轨迹公开可关（`expose_read_status`）；导出只取库主人账号，其他账号一律不参与 |
| NFR-16 | 数据保护 | 派生数据可重算，但**人工投入不可再生**（人工否决、出版社归一表、外部缓存）→ 必须纳入夜备 |
| NFR-17 | 安全 | 能接触 calibre 卷的容器只有那个几十行、无网络访问的快照 CronJob；Web 应用永不挂 calibre 卷 |

## 7. 验收标准

按 [roadmap.md](roadmap.md) 的分期，每期都必须能独立验收。

| ID | 期 | 验收标准 |
|----|----|----------|
| AC-P0 | 阅读状态补录 | 三个书架已建；54 本候选池逐本处理完；已读的书补了个人星级 |
| AC-P1 | 元数据修复 | 每本书都有 `pubdate_source`；能报出 `mtime-fallback` 剩余数量；出版社归一表覆盖 Top 20 出版社 |
| AC-P2 | 离线打分 | ① `timeless` 榜前 20 名经**人工逐本核对**无明显误入；② `to-read-next` 能出结果；③ 抽 30 本核对 HN 提及命中的确是这本书；④ 同版本重跑分数逐位一致 |
| AC-P3 | Web 上线 | 公开可访问；每本书能展开得分拆解；阅读状态徽章与筛选可用；限流已生效；C 级书标注"数据不足" |
| AC-P4 | 收尾 | 指标进监控；标准文档定版；新 PVC 已在夜备名单里 |

**AC-P2 ① 是硬门槛**：榜首若出现明显不该在的书，**回头改公式，不许靠调权重糊过去**
—— 调权重能让任何一版烂公式在小样本上"看起来对"。

## 8. 约束与假设

### 约束

| ID | 约束 |
|----|------|
| C-1 | 目标集群 `oracle-k3s` 是 ARM free tier，单节点 |
| C-2 | 部署清单真相源在 **homelab 仓库**，ArgoCD 不指向本仓库 |
| C-3 | 镜像策略受集群 Kyverno 策略约束（禁 `latest` tag） |
| C-4 | 新 PVC 必须有备份归属，否则 homelab 的 CI 会拦（规则 H4） |
| C-5 | 存储一律 `local-path`；SQLite 应用不用网络存储 |
| C-6 | 新子域名不需要改 DNS/隧道配置（通配隧道 + external-dns 自动建记录），只需一个 HTTPRoute |
| C-7 | 域名**不用 `books.`** —— 与私有书库 `book.meirong.dev` 只差一个字母，误配代价高 |

### 假设（若不成立需重新评估）

| ID | 假设 | 若不成立 |
|----|------|---------|
| A-1 | Google Books 对本库技术书的评分覆盖率能达到 ISBN 命中的多数 | 口碑维度可用书数大幅下降，A/B 级书可能不足 500 本 |
| A-2 | HN 提及数是技术圈口碑的有效代理 | 社区声量维度退化为噪声，应直接降权或砍掉 |
| A-3 | LLM 能从"标题 + 出版社 + 简介"稳定判断深度与主题类别 | 深度/可操作维度需人工标注，规模不可行 → 退回 4 维 |
| A-4 | 库主人愿意持续在 calibre-web 里标记阅读状态 | 阅读状态相关功能长期只覆盖 1% 的书，US-1/US-7 失效 |

## 9. 风险登记

完整分析见 [roadmap.md §风险](roadmap.md#风险登记)。最高的三条：

| 风险 | 影响 | 缓解 |
|------|------|------|
| ⚠️ `pubdate` 污染未修就上时效维度 | "今年新书"榜塞满老书，整站可信度一次性崩塌 | FR-13 设为**阻塞**前置；来源不可信即记"未知"，不参与排序 |
| ☠️ 整库快照 `app.db` | 密码 hash / OIDC 凭据落到公开服务能读到的卷上 | NFR-13 最小导出；写进代码 review 清单 |
| HN 标题误匹配 | 通用短标题命中大量无关讨论，榜单显得随机 | 精确短语 + 作者/出版社共现约束；≤2 词标题走白名单；保留 objectID 可人工否决 |

## 10. 开放问题

| # | 问题 | 倾向 |
|---|------|------|
| 1 | 公开范围只发 A/B 级（约 700–900 本），还是也放 C 级目录页？ | 放目录页，但默认榜单不含 C |
